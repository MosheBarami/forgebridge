# The 50 milestones

> **Provenance note, read this first.** The original numbered list of 50 milestones is not
> present anywhere the maintainer can find it — not in the planning directory, not in this
> repo's `docs/`, and not in the memory file. What follows is a **reconstruction** built from the
> categories named in the brief (backend, optional auth, projects, generation, inventory,
> game map, settings, deployment, Studio plugin, persistence, testing, security,
> observability, self-hosting, community) plus the new bridge/open-source scope. Confirm or
> correct the numbering before it is treated as a contract; the *content* is what matters
> and it is complete.

## How to read a row

Every row is now decided against **this tree**, not against the repository this project
replaced. Two columns say so, and they are deliberately about different things:

- **`#`** carries the milestone id and, when the work is finished here, a **✅**. That tick is
  the only claim in this document that a milestone is *done*. A row without one is not done,
  and its **Definition of done** cell opens with **Partial —**, **Not started —** or
  **Removed —** so the reader is told which without counting ticks.
- **`Was`** is the status of that work in the **predecessor** repo at HEAD `b174ec2`, and it
  never changes: `NEW` (did not exist), `PART` (existed, needed rework for the
  open-source/bridge model), `DEL` (existed and had to be removed under the free-forever
  constraint). It is provenance. It is not a statement about today, and older prose elsewhere
  in the repo that says "M45 is status NEW in `MILESTONES.md`" is reading this column.

Until this audit those two facts shared one column and one tick, and they disagreed twice in
ways a reader could not resolve: `M17` carried a ✅ *and* the sentence "Still `PART`", and
`M31`'s id cell read `M31 PART`. Both are fixed. The rule from here is the one the rest of the
repository already applies to itself — **a row marked done whose definition of done is half met
is a defect, so where only half is met the row says which half and keeps the tick off**.

`scripts/__tests__/milestone-claims.test.ts` is the gate for that rule. It exists because the
gate that already reads every markdown file, `scripts/__tests__/docs-claims.test.ts`, is
structurally unable to see this one: D1, D3 and D6 forgive any claim whose surrounding unit carries
a milestone marker, a table row is its own unit, and every row here begins with one. That
exemption is right for a README sentence promising `packages/opencloud` at M48. It is exactly
wrong in the document whose job is to say which of those promises have been kept, so the new
gate re-checks done rows without it.

**Live status, 27 Aug 2026.** Twelve TypeScript packages — `packages/protocol`,
`packages/core`, `packages/daemon`, `packages/model-registry`, `packages/luau-analysis`,
`packages/mcp`, `packages/a2a`, `packages/cli`, `packages/conformance`,
`packages/storage-sqlite`, `packages/sdk-ts` and `packages/opencloud` — plus one Python
package, `packages/sdk-python`, and two apps, `apps/relay` and `apps/web`. The last two
TypeScript packages in that list did not exist when this audit began and were still being
written when it ended; `M29` and `M48` say what each still owes and neither carries a tick,
for the reason the note below the next paragraph gives. Everything else is green:
the TypeScript packages and both apps under Vitest, `sdk-python` under pytest and ruff, the
gate self-tests under `scripts/`, and 230 Luau plugin tests run by hand.

Per-suite counts are deliberately not rolled up here. This line read "311 gate self-tests" when
the suite had 313, and the `M10` row read 64 when `luau-analysis` had 71 — which is what a number
nothing decides does. So the rule is the one the rest of this repository already applies to its
claims: a count stays in a hand-maintained document only where a gate can decide it against the
tree. Four can, and each is read out of the tree rather than transcribed — the `protocol`
suite's 61 tests and the plugin's 230 Luau tests, both counted by
`scripts/__tests__/docs-claims.test.ts`; the workspace list in the paragraph above and the
catalog figures in the next one, both counted by `scripts/__tests__/milestone-claims.test.ts`.
The TypeScript suites cannot be counted that way: they lean on `it.each`, so a static
count of `it(` under `scripts/` misses about a third of what runs, and a gate that is
confidently wrong is worse than no gate. Every other number lives where it is produced —
`npm run test`, `npx vitest run --dir scripts`, and `python -m pytest` in `packages/sdk-python`.

`M20`'s catalog is real and its figures are now decided against
`packages/model-registry/data/catalog.json` rather than remembered:
416 models upstream, 16 free and tool-capable, 3 excluded with stated reasons.
This paragraph said 417 until this
audit, which is the count the very first sync saw; upstream dropped one within a day, the
generator's own header records that it did, and the sentence here went on saying 417 because
nothing read it.

**Eight rows were being built while this audit ran, and are marked as such.** This document
was audited row by row against the tree on 27 Aug 2026. Other agents were landing work in the
same tree at the same time, and `M19`, `M22`, `M23`, `M24`, `M29`, `M42`, `M47` and `M48`
each grew files between the start of the audit and the end of it — three of them after their
row had already been written once, which is why it was written again. Those rows say so in place, describe
only what could be decided regardless of how far the new code got, and **none of them carries a
tick**: a milestone marked done by somebody who did not read the finished thing is the precise
defect this audit exists to remove, and it does not become acceptable when the unread thing is
probably fine. Whoever finishes one of them owns moving its row — and
`scripts/__tests__/milestone-claims.test.ts` will refuse a tick whose evidence does not exist.

Two holes in the frozen protocol were found by adversarial review and closed before the first
public commit: `setProperty` could write `Parent`, which relocated an entire subtree while
reporting only its source path and so slipped the policy allowlist, the bulk-delete counter
and the auto-apply exclusion simultaneously; and `InstanceRef` carried an unvalidated string
that `pathsOf` never reported, so a reference could point anywhere the allowlist was never
shown. Both are fixed, and both are pinned by tests in
`packages/protocol/test/changeset.test.ts` — `refuses setProperty on Parent`, and the `pathsOf`
cases that report an `InstanceRef` target from a `setProperty` and from a `createInstance`
property bag. Recording it here, with the file, because "the review process works" is a claim
that needs evidence like any other.

**Critical path**: M07 → M09 → M14 → M15. Nothing else matters if a ChangeSet cannot make
it from a producer into an open Studio session and back out again. Three of those four are
done; `M15` is the last one, and what it owes is listed on its row rather than described as
polish.

**Gate before Phase 5**: no product surface is rebuilt until the protocol is frozen. The
protocol is frozen and Phase 5 is under way — the gate held, and what the surfaces are waiting
on now is not the protocol but each other: `M37` cannot draw until `M34` writes a snapshot and
`M35` keeps a ChangeSet, and `M38`'s approval policy cannot bind until `/v1` grows a route
that accepts one.
